Critical Flow 3: Node Composition Execution

sequenceDiagram participant Client participant API as API Route participant ORCH as Orchestration Service participant REG as Node Registry participant NODE1 as Node 1 participant NODE2 as Node 2 participant NODE3 as Node 3 Client->>API: POST /api/nodes {action: "suggest-composition", goal} API->>ORCH: suggestNodeComposition(goal, context) ORCH->>REG: getAllNodes() REG-->>ORCH: Available nodes ORCH->>AI: Analyze goal and suggest composition AI-->>ORCH: {nodes: [], connections: []} ORCH-->>API: Composition suggestion API-->>Client: Suggested composition Note over Client,NODE3: Execution Phase Client->>API: POST /api/nodes {action: "execute-composition", compositionId, params} API->>ORCH: executeNodeComposition(compositionId, params) ORCH->>REG: executeComposition(compositionId, params) REG->>NODE1: executeNode(nodeId, params) NODE1-->>REG: Result 1 REG->>NODE2: executeNode(nodeId, result1) NODE2-->>REG: Result 2 REG->>NODE3: executeNode(nodeId, result2) NODE3-->>REG: Result 3 REG-->>ORCH: Final result ORCH-->>API: Composition result API-->>Client: Execution result

Composition Model

  • Sequential execution nodes run in order, outputs become next inputs
  • Fail-fast abort on first failure (configurable)
  • Per-node timeout enforced at execution layer

Error Handling & Recovery

  • Node Not Found graceful error with clear message
  • Validation Errors detailed per-field info
  • AI Failures fallback to basic search
  • Tool Failures retries + backoff
  • Network Failures timeout + retry
